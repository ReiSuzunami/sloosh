## Design Context

### Users

Sloosh is used by developers and operators who let coding agents work through
persistent SSH sessions. The desktop app is a local security control surface:
users check whether Sloosh is ready, install the Agent Skill, initialize the
vault, and configure Touch ID or a six-digit fallback PIN.

### Brand Personality

Calm, trustworthy, and precise. The product should feel like a focused macOS
security utility: technically capable without exposing implementation detail as
the primary experience. Approval should feel deliberate, never alarming or
playful.

### Aesthetic Direction

Refined industrial minimalism. Use quiet neutral surfaces, a single amber
human-approval accent, and green only for verified readiness. Preserve the loop
and terminal mark as the main visual identity. Support light and dark system
appearances. Avoid decorative gradients, glass effects, marketing layouts,
repeated card grids, oversized typography, and generic developer-dashboard
styling.

### Design Principles

1. Lead with security readiness, its exact blocker, and one next action.
2. Keep runtime internals available under progressive disclosure.
3. Make setup continuous and explain why unavailable actions are blocked.
4. Use native interaction patterns, clear focus states, non-color status cues,
   reduced motion, and WCAG AA contrast as the baseline.
5. Keep Light, Dark, and Mono icon geometry identical; change appearance, not
   identity.
